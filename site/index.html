Weekly status for several client projects, from one YAML file each.

With a handful of clients it is easy to notice an overdue project or a stuck blocker late. client-pulse reads one YAML file per project and prints what is late, what is blocked and where hours ran over, plus a weekly report in Markdown. Nothing here is real client data.

03

YAML schema

One project per file. Unknown fields, bad dates and wrong types are reported with the file, the line and what to fix. The table is built from schema.json, and a test checks that file against the fields the loader actually accepts. 

name: Acme website refresh
client: Acme Bakery
status: active
next_milestone: Homepage review call
deadline: 2026-03-20
blockers:
  - Waiting for product photos from the client
hours_estimated: 40
hours_spent: 31.5
Project file fields
Field Required Type Notes
name yes text Project title. Must be unique across files (case-insensitive).
client yes text Client display name.
status yes active | on-hold | done done projects are excluded from overdue, blockers and over-estimate checks.
deadline yes date Due date as YYYY-MM-DD. A project due today is not overdue.
hours_estimated yes number Planned hours.
hours_spent yes number Hours already spent.
next_milestone no text Optional short label for the next checkpoint.
blockers no list of text Optional open blockers. Ignored when status is done.
04

What works

  • works list, overdue, blockers and weekly-report, each with --json
  • works YAML validation with file, line and a fix hint, including duplicate project names across files
  • partial Posting the report to a webhook or Telegram. It is tested with mocked HTTP only; I have not run it against a live service.
  • not done Filters by client or status, and a PyPI release. Install from a clone.

06

How I built it

ruamel.yaml for line numbers

Error messages are only useful if they point at the line. ruamel.yaml's round-trip loader keeps the position of every key and list item, and it is pure Python, so it installs on every Python version I test.

Today is an input

Overdue depends on the date, so every command takes --today (or CLIENT_PULSE_TODAY). The tests and the output on this page use a fixed date instead of the clock.

All files are checked before anything is printed

A half-valid directory would give a report that silently misses projects. If any file is invalid the command lists every problem and exits with code 1.

07

Limits and roadmap

  • Deadlines are dates without a time zone. "Today" is the system date unless you pass --today.
  • One project per file; a single file with several projects is not supported.
  • There is no web editor. This page is a static sample.

What comes next is tracked in the open issues. To contribute, start with CONTRIBUTING.md.
